VERDICT: SHIP WITH FIXES — The conversion is correct and the parity, speed and run numbers reproduce from the committed files, but several headline claims go further than the evidence, the safety guard misses common risky actions, and the adb test hooks can turn the guard off in every build.

Review of commit `9fa3ca3` (detached worktree). Read-only throughout: no phone, adb or emulator was used. The only build was the unit tests inside the worktree. The vision-patch deep dive was delegated to a sub-agent; its findings are marked "(sub-agent)", and I spot-checked its key evidence.

## Could not check

- **Anything on a phone:** GPU vision precision on non-Adreno GPUs; landscape; whether the screenshot orientation matches gesture coordinates when rotated; typing, scrolling and long press. No device use was allowed.
- **Pillow version of the training images:** they were built on Colab with Pillow unpinned. Pillow 13 (released 2026-10-16) added the vertical-first pass that `Resample.kt` copies; Pillow 12.x and earlier always run the horizontal pass first, which can give ±1 rounding differences. The research repo's local venvs have 13.0.0, so this is probably fine.
- **Whether LiteRT-LM's prefix dedup goes through image tokens.** Inferred no, because the shared-engine and per-row outputs agree on 28/30 rows, but not verified in code.
- **The DUMP protection level on Android 17 specifically:** stated from AOSP knowledge.
- **Thermal state during the phone benches:** not recorded.
- **Whether the Android AAR uses stb or Skia for the resize:** inferred stb from library strings (sub-agent).
